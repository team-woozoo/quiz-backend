# 퀴즈 생성 품질 기록

AI 연결부터 지금까지 생성 품질을 어떻게 바꿔 왔는지 시간순으로 남긴다. 표본이 적은 측정은 결론이 아니라 관찰로 적는다.

강의 자료 원문, 생성된 문제의 내용, 게이트웨이 주소와 키는 적지 않는다. 자료는 쪽수와 글자 수로만 구분한다.

## 측정 환경

| 구분 | 내용 |
|---|---|
| 게이트웨이 모델 | `bedrock-haiku`(Claude Haiku 4.5), `bedrock-sonnet`(Claude 3.5 Sonnet v2), `bedrock-gpt-5.6-luna` |
| 자료 A | 20쪽, 6,962자 |
| 자료 B | 30쪽, 12,312자 |
| 목표 유형 | 10문제 기준. 2026-11-09 전은 모든 난이도가 기억 2, 이해 2, 적용 3, 분석 2, 평가 1. 그 뒤 EASY 는 기억 4, 이해 3, 적용 3 |

## 2026-11: 다른 모델의 유형 판정

조건: 생성 luna, 판정 `bedrock-sonnet`, temperature 0. 판정 모델에는 생성기의 유형을 보내지 않는다. 두 유형이 같은 문제만 저장한다.

### 2026-11-07 1회차 (자료 A, 일반 객관식)

| 단계 | 결과 |
|---|---|
| 생성 | 10문제 요청에 3문제, 11.3초, 입력 7,663 / 출력 1,543 토큰 |
| 규칙 검증 | 3개 모두 통과 |
| 판정 | 6.9초, 입력 4,594 / 출력 325 토큰 |
| 일치 | 3개 중 3개. 기억 2, 이해 1 |

관찰: 판정 모델 호출과 JSON 스키마가 게이트웨이에서 동작했다. 고차원 문제가 없어 판정 품질은 알 수 없다. 3문제만 나온 원인은 확인하지 못했고, 이전 일반 퀴즈 10개의 최소는 8문제였다.

### 2026-11-07 2회차 (자료 A, 일반 객관식)

| 단계 | 결과 |
|---|---|
| 생성 | 13문제, 19.8초, 입력 7,663 / 출력 4,257 토큰 |
| 규칙 검증 | 버린 문제 0개, 넘쳐서 3개 제외(이해, 적용, 분석 1개씩) |
| 판정 | 10문제, 16.5초, 입력 8,590 / 출력 911 토큰 |
| 일치 | 10개 중 5개 |

| 생성 유형 | 문제 수 | 일치 | 불일치 판정 |
|---|---|---|---|
| 기억 | 2 | 2 | 없음 |
| 이해 | 2 | 1 | 기억 1 |
| 적용 | 3 | 1 | 이해 1, 기억 1 |
| 분석 | 2 | 0 | 적용 1, 기억 1 |
| 평가 | 1 | 1 | 없음 |

관찰: 불일치 5개는 모두 낮은 쪽이었다. 저장된 퀴즈에는 분석 문제가 없었다. 판정 전에 잘린 3문제에는 적용과 분석이 있었다.

판단 보류: 직접 검토했을 때 부풀림은 퀴즈당 1~2개였는데 이번 판정은 5개를 낮췄다. 생성기의 부풀림인지 판정의 엄격함인지는 불일치 문제를 사람이 판정해야 알 수 있다.

### 2026-11-07 3회차 (자료 A, 일반 객관식)

| 단계 | 결과 |
|---|---|
| 생성 | 10문제, 22.4초, 입력 7,663 / 출력 4,141 토큰 |
| 규칙 검증 | 버린 문제 0개, 넘쳐서 뺀 문제 0개 |
| 판정 | 10문제, 17.7초, 입력 8,872 / 출력 972 토큰 |
| 일치 | 10개 중 5개 |

| 생성 유형 | 문제 수 | 일치 | 불일치 판정 |
|---|---|---|---|
| 기억 | 2 | 2 | 없음 |
| 이해 | 2 | 1 | 기억 1 |
| 적용 | 3 | 1 | 이해 2 |
| 분석 | 2 | 1 | 이해 1 |
| 평가 | 1 | 0 | 분석 1 |

관찰: 불일치 5개가 이번에도 모두 낮은 쪽이었다. 2, 3회차를 합치면 고차원 문제 12개 중 4개가 일치했다.

사람 판정 초안(불일치 5개, 확정 전): 판정이 맞음 3개, 생성 유형이 맞음 1개, 경계 1개. 판정이 맞은 문제는 인용의 내용이나 코드를 그대로 고르면 풀렸다. 생성 유형이 맞은 문제는 자료의 코드에서 반복 횟수를 바꾼 쉬운 적용 문제로, 판정이 쉬움을 낮은 유형으로 본 경우다. 경계 문제는 조건 하나로 대안이 정해져, 평가로 보기에도 분석으로 보기에도 근거가 약했다.

### 2026-11-07 4회차 (자료 A, 일반 객관식)

판정 프롬프트에 "유형은 난이도가 아니다. 쉽게 풀려도 새 조건에 규칙을 적용해야 하면 APPLY 다"를 추가한 뒤 측정했다.

| 단계 | 결과 |
|---|---|
| 생성 | 11문제, 19.7초, 입력 7,663 / 출력 3,669 토큰 |
| 규칙 검증 | 버린 문제 0개, 넘쳐서 분석 1개 제외 |
| 판정 | 10문제, 15.3초, 입력 8,883 / 출력 828 토큰 |
| 일치 | 10개 중 6개 |

| 생성 유형 | 문제 수 | 일치 | 불일치 판정 |
|---|---|---|---|
| 기억 | 2 | 2 | 없음 |
| 이해 | 2 | 2 | 없음 |
| 적용 | 2 | 1 | 분석 1 |
| 분석 | 2 | 0 | 이해 2 |
| 평가 | 2 | 1 | 분석 1 |

관찰: `APPLY->UNDERSTAND` 는 사라졌지만, 코드를 바꿔 페이지 수를 묻는 같은 꼴의 문제가 이번에는 `APPLY->ANALYZE` 로 판정됐다. 처음으로 높은 쪽 불일치가 나왔다. 규칙 추가의 효과라고 말하기에는 표본이 적다. 생성 유형은 목표(적용 3, 평가 1)와 달리 적용 2, 평가 2 였고, 지금 구조는 이 차이를 바로잡지 못한다.

사람 판정 초안(불일치 4개, 확정 전): 판정이 맞음 2개, 생성 유형이 맞음 1개, 경계 1개. 3, 4회차를 합치면 불일치 9개 중 판정이 맞음 5개, 생성 유형이 맞음 2개, 경계 2개다.

## 2026-11: 난이도별 유형 비율

조건: 판정 조건은 위와 같다. EASY 는 분석과 평가를 빼고 기억 4, 이해 3, 적용 3 을 요청한다. NORMAL 은 그대로다. 고차원 문제의 불일치가 많아, 쉬운 난이도에서 고차원 유형을 빼면 얼마나 남는지 본다.

### 2026-11-09 5~7회차 (자료 A, EASY 객관식)

| 회차 | 생성 | 규칙 검증 | 판정 | 일치 |
|---|---|---|---|---|
| 5 | 11문제 (기억 4, 이해 5, 적용 2) | 넘쳐서 이해 1개 제외 | 10문제 | 10개 중 8개 |
| 6 | 10문제, 13.9초, 입력 7,658 / 출력 2,584 토큰 | 버린 문제 0개 | 16.7초, 입력 8,433 / 출력 887 토큰 | 10개 중 8개 |
| 7 | 11문제, 14.8초, 입력 7,658 / 출력 2,753 토큰 | 넘쳐서 기억 1개 제외 | 14.0초, 입력 8,215 / 출력 784 토큰 | 10개 중 7개 |

5회차의 생성과 판정 시간, 토큰은 남기지 않았다.

| 생성 유형 | 문제 수 | 일치 | 불일치 판정 |
|---|---|---|---|
| 기억 | 12 | 12 | 없음 |
| 이해 | 10 | 7 | 기억 3 |
| 적용 | 8 | 4 | 이해 3, 기억 1 |
| 합계 | 30 | 23 | |

관찰: 일치는 30개 중 23개(77%)로, NORMAL 2~4회차의 30개 중 16개(53%)보다 높다. 적용은 8개 중 4개로 NORMAL 의 8개 중 3개와 큰 차이가 없다. 불일치 7개는 모두 낮은 쪽이었다. 생성 출력 토큰은 NORMAL 의 3,700~4,300 에서 2,600~2,800 으로 줄었다. 생성기는 세 번 중 한 번 적용을 2개만 내고 이해를 5개 냈다. 원문 문장을 정답 보기로 옮긴 같은 문제가 5, 7회차에 다시 나왔다.

사람 판정 초안(불일치 7개, 확정 전): 판정이 맞음 5개, 경계 2개, 생성 유형이 맞음 0개. 판정이 맞은 문제는 원문 문장을 정답 보기로 옮겼거나, "자료의 방법에 따라"처럼 자료 코드의 호출을 그대로 고르면 풀렸다. 경계 2개는 새 값이나 개수를 주지만 정답이 그 값을 그대로 옮기거나 그 값 없이도 보기를 고를 수 있어, 적용으로 보기에 근거가 약했다.

판단과 다음 조치: 고차원 유형을 빼면 남는 문제는 늘지만 적용의 일치율은 그대로다. 적용 문제의 약점은 난이도가 아니라 새 조건 없이 자료 코드를 되묻는 꼴에 있다. 넉넉히 생성해 유형별로 고르는 단계(Phase 23)에서 적용을 더 받아야 한다. 같은 자료로 다시 만들 때 같은 문제가 나오는 것은 Phase 24 의 중복 회피에서 다룬다. NORMAL 비율은 그대로 둔다. NORMAL 에서 평가를 빼면 HARD 를 풀지 않는 사용자의 평가 축이 비기 때문이다. NORMAL 의 분석과 평가가 계속 맞지 않으면, 그 유형을 자료 밖 심화 문제 2~3개로 내는 쪽을 검토한다.

## 남은 질문

- 불일치 문제에서 생성 유형과 판정 유형 중 어느 쪽이 맞는가
- 일치만 저장하는 정책이 유지될 만큼 문제 수가 남는가
- 13문제를 받아 판정한 뒤 고르면 고차원 문제가 얼마나 남는가
- 같은 입력에서 생성 문제 수가 3개와 13개로 갈린 원인은 무엇인가
- 생성 프롬프트에서 적용 문제의 조건(새 조건을 실제로 써야 풀린다)을 강조하면 적용 일치가 오르는가
